# 알지오매스 키즈 정밀 분석

- 대상: https://www.algeomath.kr/kids
- 운영/주관: 교육부 지원, 한국과학창의재단 주관
- 조사 기준: 2026-11
- 소스 공개 여부: **[UNKNOWN] 현행 핵심 소스 저장소 확인되지 않음**
- 분석 근거: 공식 사이트, 2025-12 사용자 매뉴얼, 온라인 매뉴얼

## 1. 서비스의 정체성

알지오매스 키즈는 단순 기하 작도기가 아니라 다음 네 층을 묶은 초등 수학 작업 환경에 가깝습니다.

1. **알지오 2D** — 점·선·도형·변환·측정·확률·통계
2. **알지오 3D** — 쌓기나무·연결큐브·입체도형·전개도·측정
3. **알지오 문서** — 2D/3D 산출물을 텍스트·이미지·동영상과 함께 편집
4. **알지오 모둠** — 게시판, 학습자 가입, 과제 제시·제출·확인

즉 '수학 객체 편집기 → 학습 자료 제작 → 수업 운영'을 한 서비스 안에서 연결합니다.

## 3. 알지오 2D

### 3.1 핵심 조작 문법

알지오 2D의 기본 문법은 전형적인 **Tool-first**입니다.

~~~text
도구 선택
  → 필요한 객체/위치 선택
  → 필요하면 수치 입력
  → 수학 객체 생성
  → 선택 팝업으로 속성 수정
~~~

예:
- 선분: 선분 도구 → 두 점 클릭
- 주어진 길이의 선분: 도구 → 시작점 클릭 → 길이 입력
- 만나는 점: 교점 도구 → 두 선 선택
- 중간 위치의 점: 중점 도구 → 두 점 또는 선분 선택
- 뒤집기: 뒤집기 도구 → 도형 선택 → 기준선 선택

이 방식의 장점은 학생이 '무슨 수학적 연산을 하고 있는지'를 메뉴 이름으로 인지한다는 점입니다.

### 3.2 객체 선택 UI

공식 매뉴얼에서 객체 선택 시 팝업을 통해 다음 종류의 속성을 수정하는 흐름이 확인됩니다.

- 색상
- 점의 모양
- 이름
- 자취
- 고정
- 숨기기
- 삭제

**설계 의미:** 속성 패널을 항상 노출하지 않고 **선택한 객체 주변/선택 상태에 맞춰 contextual UI**를 띄우는 방식입니다.

### 3.3 그룹 선택과 종속 삭제

여러 객체를 드래그 선택하여 그룹화/해제할 수 있습니다.

또한 공식 매뉴얼은 객체 삭제 시 그 객체를 이용해 만들어진 객체도 함께 삭제될 수 있음을 설명합니다.

이 부분은 매우 중요합니다.

**[INFERRED]** 내부에는 최소한 다음과 같은 의존 관계 추적이 존재할 가능성이 큽니다.

~~~text
source object
  ↓
dependent object
  ↓
dependent object ...
~~~

예를 들어 교점이 두 선에 의존한다면 부모 선 삭제 시 교점도 무효화/삭제해야 합니다.

단, 실제 내부 자료구조가 graph인지 별도 참조 목록인지는 공개 근거가 없어 단정하지 않습니다.

## 4. 수학 객체를 의미 있는 도구로 제공하는 방식

알지오매스 키즈의 좋은 특징은 단순한 primitive drawing보다 **수학적 의미를 가진 생성 명령**이 많다는 점입니다.

### 점
- 자유 점
- 대상 위의 점
- 만나는 점
- 중간 위치의 점

### 선
- 선분
- 주어진 길이의 선분
- 직선
- 반직선 등

### 도형
- 정삼각형
- 직각삼각형
- 이등변삼각형
- 자유 삼각형
- 정사각형
- 직사각형
- 사다리꼴
- 평행사변형
- 마름모 등

### 변환
- 밀기
- 뒤집기
- 점대칭 등

### 측정
- 길이
- 각도
- 둘레
- 넓이

이 방식은 초등학생에게 '조건을 직접 설정하는 범용 도구'보다 접근성이 좋습니다.

반대로 기능 수가 늘수록 **도구 탐색 비용**이 커질 수 있습니다.

## 5. 변환 도구의 상태 머신

뒤집기 사례를 상태 머신으로 다시 표현하면 다음과 같습니다.

| 상태 | 사용자 행동 | 다음 상태 | 수학적 의미 |
|---|---|---|---|
| idle | 뒤집기 선택 | await-shape | 반사 연산 시작 |
| await-shape | 도형 클릭 | await-axis | 피연산자 고정 |
| await-axis | 기준선 클릭 | committed | 선대칭 결과 생성 |
| committed | 결과 확인 | idle | 연산 종료 |

이 구조를 범용화하면 평행이동·회전·선대칭·점대칭을 하나의 Transformation Tool Framework로 묶을 수 있습니다.

## 6. 3D 구조

공식 매뉴얼의 3D 도구 체계는 다음처럼 분리됩니다.

- 시점 변환
- 정보창
- 쌓기나무
- 연결큐브
- 입체도형
- 전개도
- 측정

### 6.1 시점과 수학 객체를 분리

3D에서는 '무엇이 존재하는가'와 '어디에서 바라보는가'가 분리되어야 합니다.

**[INFERRED] 추천 모델**

~~~text
Scene State
  ├─ Cubes / Solids / Nets
  └─ Object properties

Viewport State
  ├─ camera position
  ├─ rotation
  ├─ zoom
  └─ projection
~~~

이 분리는 사용자가 시점을 돌렸을 때 수학 객체 자체가 바뀌지 않도록 하는 기본 조건입니다.

### 6.2 측정 피드백

공식 매뉴얼은 입체도형을 클릭해 겉넓이/부피를 표시하고, 관련 정보와 계산식을 볼 수 있다고 설명합니다.

이는 단순 계산 결과만 주는 것이 아니라

~~~text
3D object
  → measure command
  → numeric result
  → formula/explanation
~~~

로 **공간 표상과 기호 표상**을 연결합니다.

## 7. 전개도

전개도 기능은 매우 중요한 비교 대상입니다.

필요한 내부 개념은 최소 다음과 같습니다.

- 면(face)
- 모서리(edge)
- 면 간 인접 관계
- 접힘 가능한 hinge
- 2D 배치 상태
- 3D 원본과 2D 전개도의 대응

**[INFERRED]** 좋은 구현은 단순 이미지가 아니라 face graph를 유지해야 합니다.

~~~text
Solid
  → faces
  → adjacency
  → unfolding transform
  → 2D net
~~~

이 구조는 별도로 개발 중인 전개도/접기 도구 분석에도 직접 연결할 가치가 있습니다.

## 8. 문서 편집기

공식 매뉴얼에 따르면 알지오 문서는 다음을 지원합니다.

- 제목/부제목
- 텍스트, 이미지, 동영상
- 2단 구성
- 첨부파일
- 요소 단위 문장 순서 편집
- 뷰 시작 위치
- 저장
- 전체화면 미리보기
- 다중 슬라이드 이동

즉 수학 작업 결과를 외부 문서 앱으로 보내는 대신 **수학 콘텐츠를 문서의 1급 객체로 다루는 구조**입니다.

### 설계적으로 가져올 점

수학 캔버스와 학습 문서를 완전히 합치기보다

~~~text
Math Artifact
  ↓ embed/reference
Learning Document
  ↓
Assignment / Share
~~~

처럼 산출물을 참조하는 편이 재사용성이 높습니다.

특히 교사가 과제 예시를 제공하고 학생이 그 예시를 기반으로 새 결과를 만드는 흐름이 중요합니다.

~~~text
Teacher artifact
  → template/example
  → student copy/attempt
  → student artifact
  → submission
  → teacher inspection
~~~

## 10. 수학 튜토리얼과 교육과정 매핑

공식 튜토리얼에는 다음과 같은 학년/주제가 확인됩니다.

- 3학년 평면도형
- 3학년 원
- 수직과 수평
- 4학년 평면도형의 이동
- 다각형
- 규칙 찾기
- 5학년 블록코딩
- 선대칭/점대칭
- 직육면체/정육면체
- 6학년 쌓기나무
- 원기둥·원뿔·구

범용 수학 도구를 그대로 노출하는 대신 **학년별 튜토리얼을 별도 층으로 올린 것**이 초등용 서비스로서 중요한 차이입니다.

## 12. 강점

1. 초등 교육과정 어휘와 도구 이름이 가깝습니다.
2. 의미 기반 수학 객체를 바로 만들 수 있습니다.
3. 2D와 3D가 한 서비스에 있습니다.
4. 문서 제작까지 이어집니다.
5. 모둠·과제 흐름이 수학 산출물과 직접 연결됩니다.
6. 전개도·쌓기나무처럼 초등 공간감각에 특화된 기능이 있습니다.

## 13. 구조적 위험

1. 도구 수가 많아지면 아이콘 탐색 비용이 커집니다.
2. Tool-first 방식은 자유로운 직접 조작보다 절차 학습이 앞설 수 있습니다.
3. 2D/3D/문서/모둠이 각각 다른 UX 문법을 가지면 서비스 전체 일관성이 약해질 수 있습니다.
4. 수학 객체의 의존관계가 복잡해질수록 삭제/Undo/복사 로직이 어려워집니다.
5. 초등 저학년에게는 명칭 중심 메뉴가 여전히 어렵습니다.

## 14. 우리 쪽에 가져올 가치가 큰 패턴

- 교육과정 친화적인 **의미 기반 도구명**
- Tool State Machine
- 원본-파생 객체 dependency
- 3D object와 camera state 분리
- solid ↔ net 대응 모델
- Math Artifact를 문서/과제에서 재사용
- 교사 예시를 학생 작업의 template로 사용
- 학년/단원에 따라 도구 세트를 제한하는 구조

## 15. 추가로 직접 검증할 항목

- 브라우저 개발자도구 기반 실제 프론트엔드 번들/네트워크 구조
- 2D 저장 파일 포맷
- 3D 저장 파일 포맷
- 객체 ID와 의존성 저장 방식
- Undo/Redo 단위
- 전개도 face-edge 데이터 구조
- 모둠 과제의 서버 API 흐름
- 로그인 없이 가능한 기능 범위
- 태블릿 터치 UX
